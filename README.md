# Kogakufuro 🌀

**光学フロー(オプティカルフロー)で、動画のFPSをその場で引き上げるWebアプリ。**
サーバーは一切使いません。動画・カメラ映像は、あなたのブラウザの外に出ることはありません。

すべての計算は WebGL2 のフラグメントシェーダ(GPU)上で完結し、書き出しも WebCodecs API で
端末内だけで行われます。

## できること

- **光学フローによるフレーム補間でFPSを上げる** — 2枚の実フレームの間でGPU上に密光学フロー
  (ピラミッド型 Horn–Schunck)を計算し、その変位場を使って中間フレームをその場で合成します
- **プレビューはリアルタイムになめらか表示** — 実フレームの取得・光学フロー計算(重い処理)と
  中間フレームの描画(軽い処理)を分離しているため、動画自体のfpsより高い頻度で画面を更新できます
  (上限はディスプレイのリフレッシュレート)
- **書き出しは動画の長さ・速度をそのままに、正確な高FPSファイルとして生成**
  ( **スローモーションにはなりません** ) — MediaRecorderではなく WebCodecs の
  `VideoEncoder` を使い、各フレームに `i / 目標FPS` の正確なタイムスタンプを与えて
  WebMファイルへ書き出すため、生成に実時間以上かかっても出力の再生速度は崩れません
- **超高精度〜爆速まで無段階調整** — 光学フローのα(平滑化)・反復回数(最大500)・
  ピラミッド段数(最大10)・処理解像度スケール(2〜100%)を自由に調整可能。
  「爆速」「超高精度」を含む5種のプリセットを搭載
- **計算解像度と出力解像度を分離** — 「処理解像度スケール」は内部の計算負荷だけを軽くし、
  プレビュー・PNG・書き出し動画は常に元映像の解像度を維持します
- 入力: 動画ファイル / Webカメラ
- 日本語 / English 切り替え、ダーク/ライトテーマ、キーボードショートカット、フルスクリーン対応
- ビルド不要 — `index.html` をブラウザで開くだけで動作(静的ファイルのみ)

## 使い方

```bash
# 依存関係なし。適当な静的サーバーで配信するか、index.html を直接開くだけ。
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

Webカメラを使う場合、ブラウザによっては `file://` から直接開くより
`http://localhost` 等から配信したほうが安定して動作します。

## 動作要件

- **プレビュー**: WebGL2 に対応したブラウザ(最新の Chrome / Edge / Firefox / Safari)、
  かつ `EXT_color_buffer_float` 拡張(ほとんどのデスクトップGPUで利用可能)
- **高FPS書き出し**: 上記に加え **WebCodecs API**(`VideoEncoder`)対応が必要です。
  現時点では最新の Chrome / Edge での動作を想定しています。未対応の環境では
  プレビューのみ利用でき、書き出しボタンは無効化されます。

## 仕組み

### 1. 光学フロー計算(GPU)
1. 入力フレーム(動画/カメラ)を Canvas 2D で処理解像度にリサイズし、WebGLテクスチャへアップロード
2. フラグメントシェーダでグレースケール化
3. ボックスフィルタで複数解像度のピラミッドを構築(段数は調整可能)
4. 最も粗い解像度から Horn & Schunck の離散微分マスクで (Ix, Iy, It) を計算し、
   ヤコビ法による反復でエネルギー最小化を解く
5. 得られたフローを1段階細かい解像度へアップサンプリング(変位量を2倍)し、初期値として次段を解く
6. 元の解像度に到達するまで繰り返し、最終的な密光学フロー場を得る

### 2. フレーム補間(FPS向上)
隣り合う2つの実フレーム A・B の間で計算した光学フロー(A→Bの変位場)を使い、
任意の位相 t (0=A, 1=B) の中間フレームを1回のフラグメントシェーダ描画で合成します。

- フレームAを `t × flow` だけ逆方向にワープしてサンプリング
- フレームBを `(1-t) × flow` だけ逆方向にワープしてサンプリング
- 2枚を t の比率でクロスディゾルブ

反復計算が不要なため非常に高速で、実フレームの取得・光学フロー計算(重い処理)と、
中間フレームの描画(軽い処理)を完全に分離できます。

### 3. 高FPS書き出し(WebCodecs)
プレビューと同じ補間ロジックで動画全体を走査し、各合成フレームを `VideoEncoder` で
エンコードします。ポイントは各フレームに **生成にかかった実時間とは無関係な、正確な
タイムスタンプ (`i / 目標FPS` 秒)を明示的に与えること** です。MediaRecorderは実時間の
キャプチャ間隔からタイムスタンプを推測するため、目標FPSが実際の描画速度を上回ると
タイミングが崩れて画質劣化やコマ落ちの原因になります。WebCodecsではその問題が起きません。
生成したチャンクは [webm-muxer](https://github.com/Vanilagy/webm-muxer)(MITライセンス、
`js/vendor/webm-muxer.js` にベンダリング)でWebMファイルへ多重化します。

## ファイル構成

```
index.html               画面構造
css/style.css             UIスタイル(ダーク/ライトテーマ対応)
js/gl-utils.js             WebGL2ヘルパー
js/shaders.js              GLSLシェーダ一式
js/optical-flow.js         ピラミッドHorn–Schunck GPU実装
js/visualization.js        フレーム補間描画・フロー場のアップサンプル
js/video-source.js         動画/Webカメラの読み込みユーティリティ
js/i18n.js                 日本語/English 辞書
js/app.js                  メインコントローラ(状態管理・ループ・UI配線・書き出し)
js/vendor/webm-muxer.js    サードパーティ製WebMマルチプレクサ(MIT, ベンダリング)
```

## プライバシー

このアプリはネットワーク通信を一切行いません(外部フォントやCDNへの依存もありません)。
読み込んだ動画・カメラ映像は、あなたの端末のメモリ上でのみ処理され、
どこにも送信・保存されません。
